# RaptiAuto

An Android app for designing and simulating Arduino and microcontroller projects — and now a 3D **Delta PLC / HMI / VFD** automation lab — on a phone, in the spirit of Wokwi. Made for RAPTI (Resonance Automation Professional Training Institute).

**Download:** [`release/RaptiAuto.apk`](release/RaptiAuto.apk) — Android 7.0+ (API 24), signed.

## New in 2.10

- **Delta PLCs drawn like the real units** (DVP16ES2, DVP32ES2, DVP20EX2): black housing, grey removable terminal blocks at the top and bottom, the wire holes with the terminal names printed exactly as on the PLC (L N ⏚ NC +24V 24G S/S X0 … and D+ D− SG D+ D− C0 Y0 …) with the AC IN / DC OUT / IN / OUT / COM2 / COM3 / A→D / D→A brackets, the STOP/RUN slide switch and round COM1 on the left, DELTA, the model and its I/O spec (8DI/8DO, 16DI/16DO, 8DI/6DO/4AI/2AO), the POWER / RUN / ERROR / COM1 / COM2 / COM3 LEDs, the IN / OUT LED grid and the **R** / **T** badge. Same layout in the 2D schematic.
- **Real terminals:** COM2 is wired on the D+ / D− / SG screw terminals. The DVP20EX2 is the **DVP20EX200T**: Y0–Y5 are NPN transistor outputs powered from **UP / ZP** (an ON output pulls its load to ZP), the analog inputs are **V0+ / I0+ / VI0−** … (±10 V, or ±20 mA with In+ bridged to Vn+) and the outputs **VO0 / IO0 / AG** (0–10 V or 0–20 mA). Saved labs are converted (AIG → VI0−, AOG → AG, C0 / C1 → ZP).
- **More of the MS300 manual:** control terminals as in chapter 6 (MI1–**MI7**, DCM, +24V, +10V, AVI, **ACI**, ACM, AFM, **MO1 / MO2 / MCM**, RA / RB / RC). New: ACI 4–20 mA / 0–10 V / 0–20 mA (Pr.03-01, 03-04, 03-12, 03-29) with signal loss 03-19 (AnL / ACE), AVI + ACI added, **PID control** (group 08: feedback 08-00, P / I / D, limits, delay, feedback loss AFE, **sleep / wake-up**), MI6 / MI7 and N.C. inputs (Pr.02-12), more MI functions (3rd / 4th accel, AVI / ACI speed, PID off, counter, FWD / REV JOG, EF1, force coast, drive enable), **MO1 / MO2** (Pr.02-16 / 02-17) and 25 output functions, the **terminal counter** (02-19 / 02-20), 4 accel / decel sets (01-12 ~ 01-19), **skip frequencies** (01-28 ~ 01-33), the V/F curve (01-03 ~ 01-08), over-torque ot1 (06-06 ~ 06-08), oH warning level (06-15), DC brake at start (07-02) and **auto-restart** after a fault (07-11 / 07-33). The transmitters can be set to 4–20 mA.

## New in 2.9

RUN, STOP, FWD and REV LEDs blink while decelerating, in standby or while the direction changes. STOP/RESET also resets faults.
- **50 Hz from every source:** ▲ ▼ on the keypad, the **speed dial** (Pr.00-20 = 7), AVI 0–10 V with bias and gain (Pr.03-03 / 03-11), the **UP / DOWN terminals** (Pr.00-20 = 3, MI = 19 / 20), RS-485 (2001H = 5000) and **15 multi-step speeds** (Pr.04-00 ~ 04-14) all reach Pr.01-00, checked by tests. - **Parameters with the manual's numbers and defaults:** groups 00, 01, 02, 03, 04, 05, 06, 07 and 09: start-up display, carrier frequency, start-up frequency 01-09, upper / lower limits, two accel / decel sets (MI = 8), JOG (01-20 ~ 01-22, MI = 6), S-curves (01-24 ~ 01-27), Pr.02-00 = 0…3 (2-wire mode 1 / 2, 3-wire), MI1–MI5 on Pr.02-01 ~ 02-05 (multi-step 1–4, reset, JOG, accel / decel inhibit, EF, B.B, output stop, force stop, UP / DOWN), relay functions incl. desired frequency 02-22 / 02-23, AFM selection and gain, motor data 05-01 ~ 05-05, stall prevention 06-01 / 06-03 / 06-04, electronic thermal relay 06-13 / 06-14, the **fault record 06-17 ~ 06-22**, DC braking at stop 07-01 / 07-03 / 07-04 and the EF / force-stop method 07-20. Saved labs from older versions are converted automatically.
- **Protection like the drive:** with stall prevention on (default) a too-short accel / decel time just makes the ramp slower; switch it off (Pr.06-03 = 0, Pr.06-01 = 0) to get **ocA** / **ovd**. Also oL, EoL1, EF, CE10 and bb. The VFD tab lists all MS300 fault codes.

## Raspberry Pi Lab (new in 2.6)

A virtual Raspberry Pi 5 / Pi 4 and Raspberry Pi Pico / Pico W / Pico 2 / Pico 2 W, without a full operating system:

- **Real Python engine:** MicroPython 1.29 compiled to WebAssembly with Asyncify (`tools/micropython/`), so `time.sleep()`, `input()` and endless loops hand control back to the app; Stop / Ctrl+C raise `KeyboardInterrupt`, and a program that ignores it is thrown away.
- **Board:** detailed top view of the chosen board with the live state of every header pin (output HIGH / LOW, PWM, input), the ACT and Pico user LEDs, BOOTSEL; a labelled GPIO strip; tap a pin for its functions and state. Parts to wire: LED, RGB LED, button, switch, buzzer (with sound), relay + lamp, servo, DC motor (L298N), PIR, HC-SR04, potentiometer (Pico ADC or Pi MCP3008), LDR, DHT22 and a NeoPixel strip.
- **Pi libraries:** `gpiozero` (LED, PWMLED, Button, Buzzer, TonalBuzzer, RGBLED, Motor, Robot, Servo, AngularServo, DistanceSensor, MotionSensor, LightSensor, MCP3008, TrafficLights, LEDBoard, CPUTemperature …), `RPi.GPIO` (BCM / BOARD, events, `wait_for_edge`, software PWM), `neopixel`, `adafruit_dht`, `board`, `signal.pause`. **Pico libraries:** `machine` (Pin with IRQs, PWM, ADC incl. the temperature sensor, Timer, RTC, WDT, `time_pulse_us`), `rp2`, `neopixel`, `dht`, `network` (Pico W, simulated Wi-Fi).
- **Desktop:** a Raspberry Pi OS Bookworm-style desktop with the raspberry menu, launchers, task bar, clock and windows for Terminal, Thonny, File Manager, Text Editor, Chromium (offline page), Calculator and Raspberry Pi Configuration (the SPI / I2C switches edit `/boot/firmware/config.txt`).
- **Terminal:** a simulated bash with pipes, `;`, `&&`, redirection and tab completion: `ls cd cat nano grep find tree head tail wc cp mv rm mkdir chmod echo history` …, `pinout`, `pinctrl` / `raspi-gpio`, `vcgencmd`, `neofetch`, `free`, `df`, `top`, `ip`, `ping`, `apt` (offline) and `python3` (files, `-c` and the interactive `>>>` prompt).
- **Thonny:** tabs, Run / Stop, Examples (15 for the Pi, 14 for the Pico, which also wire their parts), the Shell with a `>>>` REPL that stays alive after a run, errors jump to their line; on a Pico it behaves like Thonny's *MicroPython (Raspberry Pi Pico)* back end (Run sends the editor text, Ctrl+D soft-reboots and runs `main.py`).
- **Files** live on the phone (an SD card for the Pi, the flash for the Pico). Not simulated: a real Linux kernel, `apt` / `pip` installs, internet, the camera, PIO programs and CPython-only libraries (numpy, OpenCV …).

## Building

The APK is built without Gradle, using the Android SDK command-line tools from Ubuntu packages (`aapt`, `dx`, `zipalign`, `apksigner`, `android.jar` API 23+) plus Node.js 20+.

```sh
cd web && npm install && cd ..
./tools/build-apk.sh          # → release/RaptiAuto.apk
```

Other scripts:

| Command | Purpose |
| --- | --- |
| `node tests/examples.mjs` | Run every example headless, with functional checks |
| `node tests/devices.mjs` | Device and library tests |
| `node tests/plc.mjs` | PLC lab: ladder/IL, the DVP instruction set (32-bit, float, clock, pulse …), CPU, Modbus, VFD keypad, wiring and full lab simulations |
| `node tests/schematic.mjs` | 2D wiring schematic: layout, wire routing through the ducts, window / crossing selection |
| `node tests/pi.mjs` | Raspberry Pi lab: MicroPython engine, gpiozero, RPi.GPIO, Pico machine, stop / Ctrl+C, the >>> shell, Python driving a wired circuit (LED, button, MCP3008, HC-SR04, DHT22, I²C LCD) and example auto-wiring |
| `tools/micropython/build.sh` | Rebuild `web/vendor/micropython/` (MicroPython WebAssembly, needs the Emscripten SDK) |
| `node tests/routing.mjs` | 3D cable routing: no cable through a device, the console or the bench, no two cables overlapping, duct runs inside the ducts |
| `node tools/icons.mjs` | Regenerate launcher icons and the splash logo from the logo SVG |
| `node tools/shot.mjs <dir> home run:<example>:<ms>` | Screenshots in a phone-sized Chromium |

## Layout

- `android/`: the native shell (a WebView with an asset server, a JS bridge for fullscreen, files, sharing and haptics).
- `web/src/sim/lang/`: the C++ preprocessor, parser, compiler and runtime.
- `web/src/sim/`: the circuit solver, netlist, simulation engine and libraries.
- `web/src/components/`: component definitions (artwork plus simulation models).
- `web/src/ui/`: the app screens.
- `web/src/examples/`: the example gallery.
- `web/src/plc/sim/`: PLC lab simulation (DVP CPU, ladder compiler/IL, MS300 drive, Modbus, HMI runtime, lab system).
- `web/src/plc/devices/`: Delta device catalogue (ports, terminals), the automatic 3D layout and the 3D cable router (`routing.js`).
- `web/src/plc/three/`: three.js scene, procedural device models, cables.
- `web/src/plc/ui/`: lab screen, 3D panel, 2D wiring schematic (`schematic.js`, switched by `scene-switch.js`), ladder editor, HMI designer, VFD view, monitor.
- `web/src/pi/`: the Raspberry Pi lab (board art, GPIO simulator, the circuit tab `circuit.js` with the board parts `circuit-parts.js`, the GPIO ↔ circuit bridge `circuit-hw.js` and example auto-wiring `autowire.js`, Python process, terminal, Thonny, desktop); `web/src/pi/py/` holds the Python libraries made for it; loaded as `pi.js` on first use.
- `web/src/ui/gestures.js`: double-tap zoom and the window / crossing selection box shared by both simulators.
