# RaptiAuto

An Android app for designing and simulating Arduino and microcontroller projects — and now a 3D **Delta PLC / HMI / VFD** automation lab — on a phone, in the spirit of Wokwi. Made for RAPTI (Resonance Automation Professional Training Institute).

**Download:** [`release/RaptiAuto.apk`](release/RaptiAuto.apk) — Android 7.0+ (API 24), signed.

## Unreleased — PLC Lab full screen, HMI pinch zoom, no current when stopped

- **Full screen in landscape:** the Lab view (2D / oblique 3D) and a second tab (Ladder, HMI, VFD, Monitor) are shown side by side only **while the simulation runs**. With the simulation stopped, full screen shows one screen at a time. The layout follows Simulate / Stop at once.
- **HMI pinch zoom:** on the HMI tab, two fingers zoom the DOP-107 picture in and out (50 % – 500 %) and move it; the ＋ / − / fit buttons at the left, the mouse wheel, one finger on the frame while zoomed and a double tap on the frame (back to fit) work too. Works when operating and when designing screens; a touch only presses an HMI button when it is a single finger, so a pinch never presses anything.
- **No current in the wires when stopped:** the moving current lights on the 3D cables kept running after Stop; they are cleared now.

## New in 2.12 — Modbus network in 3D

- **Modbus RS-485 devices for the PLC Lab** (＋ → *Modbus RS-485 devices*): a **Delta DTB4848** PID temperature controller heating a small oven (PV red / SV green display, OUT1 / AT / ALM LEDs, SET ◀ ▼ ▲, the heater glows with its output), an **RS-485 temperature & humidity sensor** with an LCD and an **energy meter** on the main incomer that measures what the panel takes (drives, supplies, PLCs, the 500 W oven heater). Each has a station address, baud rate, data format (8N1 / 8E1 / 7E1 …) and RTU / ASCII in its settings, RS-485 terminals printed D+ / D− or A+ / B−, and TX / RX LEDs that blink with every frame.
- **One RS-485 line, many slaves:** the PLC COM2 (MODRW) is the master of drives, other PLCs and these devices on a daisy chain (each RS-485 port takes two cables, their wires go into the same terminals). Every slave answers with its own register map: DTB4848 1000H PV, 1001H SV, 1002H / 1003H range, 1005H control (PID / ON-OFF / manual), 1012H output %, bit 0814H RUN / STOP; sensor 0000H temperature, 0001H humidity, 0002H dew point (function 03 or 04); meter 0000H V, 0001H A, 0002H W, 0003H PF, 0004H Hz, 0005H / 0006H Wh (32-bit, low word first). Like the real thing: a wrong address stays silent, an unknown register answers exception 02, a value out of range 03, an unsupported function 01; a different baud rate / format is not understood (time-out), and **two slaves with the same address both answer and their replies collide**. Lab check explains each of these.
- **MODRW speaks every function:** 01 / 02 (read bits, packed 16 to a register), 03 / 04 (read words), 05 / 15 (write bits), 06 / 16 (write words) — also against a DVP slave PLC.
- **Network view (the Network chip in the Lab tab):** the 3D panel becomes an x-ray of the communication — power wiring, ducts and the devices that do not communicate fade out, the scene dims, and the **RS-485 cable glows violet, RS-232 amber, USB blue**. Every device carries a tag with its role and address (MASTER, ID 1 … ID 4, the serial format), every comm port its name (COM2 · RS-485 · D+ D− SG, RJ45, mini-DIN 8, D-sub 9, mini-USB), the line its bus label, and the two ends of the RS-485 line show their **120 Ω terminating resistors**. Labels keep their size on screen and switch to a compact badge when far away.
- **Every frame travels the real cable** *(2.13: the moving packets were replaced by the stations' ports pulsing white when asked, green when they answer, red on a time-out)*: while the lab runs, each request of the master is an **amber packet** running from PLC COM2 through the ducts and the daisy-chained terminals to the station it is addressed to, the reply a **green packet** back; an exception or a time-out flashes **red** ("no reply"). The HMI ↔ PLC polls run on the RS-232 cable the same way. Zoomed in, each packet shows what it carries ("ID 2 ◂ Read PV, SV 1000H", "▸ PV 146.9 °C · SV 150.0 °C"). A legend card shows the bus format, the master and live TX / RX / time-out counters.
- **Monitor → Network:** every comm line as it is cabled — the RS-485 bus drawn as a chain from the master to the last station with its 120 Ω ends, the RS-232 HMI link and the USB programming link — with the live state of each station (OK / no reply / idle), its last values, and (tap it) its **register map with live values**.
- **Cable pin-outs:** tap a communication cable → **Pin-out**: both connectors drawn with their pins and the wires between them (RS-485 D+ → D+ / SG+ on the MS300 RJ45 pin 5, D− → pin 4, GND pin 3; RS-232 crossed TX ↔ RX: DVP COM1 mini-DIN pins 4 / 5 / 8 ↔ DOP COM1 D-sub pins 3 / 2 / 5), the station and format both ends are set to, and the rules of the bus.
- **New lab exercise "Modbus RTU network: PLC · VFD · DTB · sensor · meter · HMI"** with 6 tasks: the oven controller holds 150 °C, the PLC starts the MS300 conveyor (station 1) only when the oven is ready, writes the HMI set value to the DTB (FC06), switches it with the RUN bit (FC05), reads the cabinet climate and the energy; two HMI screens (line + network). Also in the 2D schematic, where the Network view fades everything but the communication.
- Other: the daisy-chained RS-485 cables on PLC COM2 land in the same D+ / D− / SG terminals; rail 2 never puts a device on the middle wire duct; MS300 replies are decoded in the comm log ("H 30.00 Hz · 1.20 A").

- **Panel-style 3D wiring (new in 2.2):** every wire is laid like in a real control panel: out of its terminal, into the nearest slotted wire duct (open at the front, so the wiring stays visible), along the duct on a track of its own, down the side or middle vertical ducts and out through the bottom duct. Front terminals (VFD, PLC comm ports) drop down on their own plane, cables on the bench go around the console, HMI stand, motor base and laptop and lie over each other where they cross, and console patch cords come over the back edge. No wire runs through a device or another wire (checked by `tests/routing.mjs`).
- **Fixed-layout ladder (new in 2.3):** the ladder always fills the width of the screen — no sideways panning or zooming. Networks are stacked as cards and the program grows downward (plain vertical scrolling); long network comments wrap, device comments sit under each contact on up to two lines, and big instruction boxes (MODRW, SCAL …) make their row taller instead of wider.
- **Many more ladder instructions (2.3):** MEP / MEF, word-logic contacts (LD& LD| LD^), ZCP, CML, BMOV, FMOV, XCH, BCD, BIN, SWAP, NEG, ABS, SQR, MEAN, SCAL, WAND / WOR / WXOR, ROR / ROL, SFTR / SFTL, DECO, ENCO, SUM, BON, master control (MC / MCR), jumps and subroutines (CJ, CALL, SRET, FEND with pointer labels P0–P255) and the step ladder (STL / RET), all simulated by the CPU and listed in a searchable instruction picker.
- **3D camera stays outside (2.3):** zooming, orbiting or panning stops just in front of a device, the enclosure, the console or the bench — the view never goes inside an object.
- **Smooth, flicker-free 3D (2.2):** no more z-fighting on the laptop and HMI screens and labels, no blank frames on resize, the laptop screen is only redrawn when it changes, the depth range follows the camera, and the resolution steps down on slow GPUs instead of stuttering. Switching 2D ↔ 3D shows "Loading 3D…" instead of freezing, never gets stuck on a lost touch, and a lost GPU context falls back to 2D.
- **Fixes in 2.3.1:** no more flicker on the top / bottom terminal strips of the PLC in 3D (the terminal blocks no longer share a face with the housing, and the 3D view asks the phone for a 24-bit depth buffer); the drive display in the 2D schematic stays inside its window; "Wire", 2D / 3D and the focus chips keep their dark glass over a bright 3D panel; in full screen every control and the ladder / HMI / VFD / monitor tool bars start below the punch-hole camera or notch.
- **Fixes in 2.3.2:** the 3D focus chips (Overview, Panel, PLC, HMI, VFD …) use the full width of the screen when the tool rail is out of the way, and fade at the edge when more can be scrolled to; the Delta PLC Lab card on the home screen no longer lays its picture over the text on wider phones (the picture goes below the buttons on any phone); in full screen the menus that ☰ brings up float on frosted (blurred) glass, and the tab bar now sits as a dock at the bottom centre with the run status just above it (above the ladder / HMI footer and the 3D focus chips), so the ladder, HMI, VFD and monitor tool bars at the top and the start of every rung stay uncovered. The programming laptop in 3D has a real keyboard: raised chiclet keycaps in a dark well with a full laptop layout (half-height function row, number row, QWERTY rows, wide Tab / Caps / Shift / Enter / Backspace, a long space bar, inverted-T arrow keys) and printed legends, plus a glass touchpad.
- **New in 2.4:** a **magnetic contactor** (3 main poles, 1NO + 1NC auxiliary, 24 V DC or 230 V AC coil, can be pushed in by hand), a **thermal overload relay** (95–96 / 97–98, test-trip and reset) and **industrial sensors**: inductive, capacitive and photoelectric sensors (PNP or NPN), a roller limit switch, a float level switch and 0–10 V temperature and pressure transmitters. New example lab *Motor starter: contactor + overload relay* with self-checking tasks. Fixes: switching from 3D to 2D no longer leaves the frozen 3D picture on screen; the online Set / Force menu on a ladder contact no longer closes right after it opens.
- **New in 2.5:** more panel parts — a **3-position selector** (FWD – 0 – REV / HAND – OFF – AUTO), a **24 V DC interface relay** with LED and test button, **circuit breakers** (1-pole control MCB or 3-pole motor MCCB, C2–C32) and a 6-way **terminal block strip**. More ladder instructions: **TON / TOF** timers, the 32-bit and high-speed counter **DCNT** (C200–C242), **FOR / NEXT** loops, **WDT**, word shift and FIFO (**WSFR, WSFL, SFWR, SFRD**), rotate through carry (**RCR, RCL**), Modbus **MODRD / MODWR** and the Delta drive instructions **FWD, REV, STOP, RDST, RSTEF**; the instruction picker is grouped 01–06 (contacts & coils, timers & counters, data & math, program flow, communication & VFD, shift & bits) and the ladder tool bar has quick LD=, MOV and ADD buttons. The HMI is closer to a real DOP-107: a real-time **clock**, **multi-state indicator**, **± / set-value buttons**, **slider**, **selector switch**, **tank**, **pipe** and **valve** symbols, a time-stamped **alarm history** with acknowledge (every alarm object is watched on every screen), a **System Setting** menu (hold the top-left corner: backlight, alarms, firmware / COM info) and a bezel with PWR / COM LEDs; the Modbus example has an Alarms screen and a drive RESET over RS-485. In full screen the ☰ menu handle sits at the bottom right and the dock has a ✕ to hide the menus, so nothing covers the Ladder tool bar.
- **Wiring in 3D:** tap a terminal, tap the other end. Panel wires with ferrules, banana patch cords on the console, real connectors for COM1 (RS-232 mini-DIN ↔ D-sub), COM2 (RS-485 ↔ RJ45) and USB. Valid ends glow; U/V/W and L/N/PE are completed automatically; a wiring list editor is included.
- **Operate in 3D:** press buttons, flip the MCB and RUN/STOP switch, tap the live HMI touch screen and the VFD keypad. LEDs, lamps, the 7-segment drive display and the motor shaft react; powered wires show current flow, busy comm cables show data pulses.

## Building

The APK is built without Gradle, using the Android SDK command-line tools from Ubuntu packages (`aapt`, `dx`, `zipalign`, `apksigner`, `android.jar` API 23+) plus Node.js 20+.

```sh
cd web && npm install && cd ..
./tools/build-apk.sh          # → release/RaptiAuto.apk
```

Other scripts:

| Command | Purpose |
| --- | --- |
| `node tests/examples.mjs` | Run every example headless, with functional checks |
| `node tests/devices.mjs` | Device and library tests |
| `node tests/plc.mjs` | PLC lab: ladder/IL, the DVP instruction set (32-bit, float, clock, pulse …), CPU, Modbus (every MODRW function, DTB4848 / sensor / meter slaves, collisions, format mismatches), VFD keypad, wiring and full lab simulations |
| `node tests/live.mjs` | The real internet layer with a fake internet: what goes out, what stays simulated, fallbacks with the real weather, sketches waiting for a real answer |
| `node tests/schematic.mjs` | 2D wiring schematic: layout, wire routing through the ducts, window / crossing selection |
| `node tests/pi.mjs` | Raspberry Pi lab: MicroPython engine, gpiozero, RPi.GPIO, Pico machine, stop / Ctrl+C, the >>> shell, Python driving a wired circuit (LED, button, MCP3008, HC-SR04, DHT22, I²C LCD) and example auto-wiring |
| `tools/micropython/build.sh` | Rebuild `web/vendor/micropython/` (MicroPython WebAssembly, needs the Emscripten SDK) |
| `node tests/routing.mjs` | 3D cable routing: no cable through a device, the console or the bench, no two cables overlapping, duct runs inside the ducts |
| `node tools/icons.mjs` | Regenerate launcher icons and the splash logo from the logo SVG |
| `node tools/shot.mjs <dir> home run:<example>:<ms>` | Screenshots in a phone-sized Chromium |

## Layout

- `android/`: the native shell (a WebView with an asset server, a JS bridge for fullscreen, files, sharing and haptics).
- `web/src/sim/lang/`: the C++ preprocessor, parser, compiler and runtime.
- `web/src/sim/`: the circuit solver, netlist, simulation engine and libraries.
- `web/src/components/`: component definitions (artwork plus simulation models).
- `web/src/ui/`: the app screens.
- `web/src/examples/`: the example gallery.
- `web/src/plc/sim/`: PLC lab simulation (DVP CPU, ladder compiler/IL, MS300 drive, Modbus, the RS-485 slaves `mbdevices.js`, HMI runtime, lab system).
- `web/src/plc/devices/`: Delta device catalogue (ports, terminals), the automatic 3D layout and the 3D cable router (`routing.js`).
- `web/src/plc/three/`: three.js scene, procedural device models (`models-modbus.js` for the RS-485 slaves), cables, and `network.js` — the data packets and the Network view.
- `web/src/plc/ui/`: lab screen, 3D panel, 2D wiring schematic (`schematic.js`, switched by `scene-switch.js`), ladder editor, HMI designer, VFD view, monitor (with `net-monitor.js`, the Network tab), the cable pin-out sheet (`comm-sheet.js`, data in `comm-info.js`).
- `web/src/pi/`: the Raspberry Pi lab (board art, GPIO simulator, the circuit tab `circuit.js` with the board parts `circuit-parts.js`, the GPIO ↔ circuit bridge `circuit-hw.js` and example auto-wiring `autowire.js`, Python process, terminal, Thonny, desktop); `web/src/pi/py/` holds the Python libraries made for it; loaded as `pi.js` on first use.
- `web/src/ui/gestures.js`: double-tap zoom and the window / crossing selection box shared by both simulators.
